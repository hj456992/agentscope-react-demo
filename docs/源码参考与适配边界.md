## 当前适配范围与未对齐项

这些差异是当前一致性边界，不是以旅行场景为理由取消要求，也不能称为“完整移植”。

- **传输协议。** 当前Chat Completions只接收文本/工具调用和完成原因；未实现Responses的`end_turn=false`、opaque compaction item、增量工具声明、模型兼容hash、world-state注解及异步候选安装。固定提交没有旧`compact_remote.rs`，实际远端实现为`compact_remote_v2.rs`及attempt/installation模块；不能把自然语言摘要称remote v2。
- **压缩策略。** 上游local保留用户上限20,000近似token；本项目6656输入字节上限更小，保留数量进一步受系统指令、摘要、工具定义剩余空间约束，边界原文可能截断并标记来源不完整。不是无损压缩。上游重注入context位置与Chat接口首条SYSTEM的表达不同。当前未接入pre/post compact hooks、后台压缩、post-turn阈值及模型切换压缩。
- **错误和调度。** 上游provider重试配置与公共Responses重试状态机未完整搬入；当前最多三次真实尝试、超时与读并发上限是应用配置。完整SDK流/网络取消和远端计算停止是不同问题。当前询问通过HTTP持久挂起恢复，而非上游交互界面；没有接入request_user_input_async。
- **Agent协议。** 当前固定角色模型工厂未暴露上游spawn的model/reasoning_effort覆盖与role优先级。send/followup的成功回执、list的字段与resident-only过滤等仍需逐项核对，不能仅以工具同名宣称完全一致。当前不提供WakeOnAgentMessages、durable sleep、residency卸载/懒加载机制。
- **恢复和关闭。** Java重启扫描并恢复RUNNING子回合；上游V2身份恢复与按需加载不是同一策略。TaskService关闭等待本地订阅归属清理，不能等同外部阻塞服务已经停机。取消后的下一次同session HTTP请求继承中断历史并新建根任务；旧子会话仍归旧任务树，不等同复用上游thread身份。取消续接和child followup分别有测试。
- **业务保护。** 身份、事务、全局限额、偏好CRUD和SideEffectLedger是Java服务边界。`KnowledgeService`与`AnswerVerifier`作为可独立复用的检索/校验组件保留，核心终答不再自动经过AnswerVerifier。字段Schema、日期格式、资源权限不是自然语言条件忠实性的证明；删除旧关键词门禁后不能宣称后者已被自动验证。

## 七项缺口补齐的上游归属（2026-10-29）

七项能力来自 `docs/项目问题及解法.md` 第三节的业务要求，不是从固定 Codex 提交逐函数移植：

| 能力 | 实现 | 上游依据与边界 |
|---|---|---|
| 2.11 统一失败分类 | `FailureClass`、`FailureClassifier` | 只覆盖当前 Chat Completions 传输和演示工具；上游 provider 重试状态机未完整搬入 |
| 2.9 压缩保真 | `ContextCompactor`、`SummaryFaithfulness` | 压缩触发、摘要请求和原子替换参照 `compact.rs`；保留优先级和 token 级忠实度为本次适配，不是上游承诺 |
| 2.14 业务语义校验 | `BusinessRules` | 演示工具内规则；上游没有可直接复用的平台级业务规则引擎，工具版本声明字段标注“尚未核实对应实现” |
| 2.13 / 2.15 纠错与快照 | `CorrectionTracker`、`RunContext` | 工具分发参照 `registry.rs`；纠错预算和工具快照为本次适配 |
| 2.8 事实校验 | `AnswerFactChecker`、`EvidenceRenderer` | 值比对为演示级确定性检查；NLI/语义校验标注“尚未核实对应实现” |
| 2.5 多 Agent 门槛 | `MultiAgentGate`、`MultiAgentPlanner` | 用户要求和业务判断；上游没有可直接复用的量化路由函数。Codex 的 `update_plan` 是 TODO / 检查清单工具，不是平台多 Agent 规划器；本项目 `plan_agents` 是确定性计划校验器，不自动派发，也不声称与上游规划器一致 |
| 2.17 循环检测 | `ToolCallLoopGuard`、`AgentCallGraph`、`SemanticLoopGuard` | 上游有调用图与等待 / 中断协议，没有可直接复用的字符语义环检测；`SemanticLoopGuard` 是本项目确定性适配，不调用模型 |
| 2.7 话题切分 | `service/TopicSegmenter` | 确定性业务规则；不是上游会话/线程身份语义，不删除会话、不改变 `sessionId` 边界 |

这些实现均不新增对外 HTTP 错误码、`Status` 枚举值或数据库表字段；内部错误码只进入工具结果、证据、事件和检查点。

关于规划器，固定提交中的 `update_plan` 是会话内的 TODO / 检查清单工具，用于记录步骤状态，不负责创建或调度多 Agent。Claude Code 核心闭源，公开 SDK 只能证明客户端工具调用行为，不能证明其存在平台级规划器。因此本项目的 `MultiAgentPlanner` 明确标注为确定性计划校验适配：它校验模型给出的计划并复用现有 `MultiAgentGate`，不冒充上游平台规划器，也不声称复刻未公开实现。
