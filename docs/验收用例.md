## 验证边界

天气、车票及资料是本地示例数据；离线模型验证运行协议，不能证明真实模型的规划效果。网络模型测试使用本机模拟 HTTP 服务，没有调用外部付费模型、真实天气/票务服务，也没有生产容量压测。AnswerVerifier 保留独立组件测试，核心最终回答不自动调用它，因此不能声称任意模型事实错误都会被自动拦截。

### 真实操作与结果口径

- 页面提供场景目录、前提、步骤、预期、关联任务和验收结果入口；选择场景不自动发请求。点击开始才创建隔离的验收会话，实际模型与既有工具执行；不做“全部一键通过”。
- 每个结果保存问题编号、步骤、真实请求字段（剔除认证）、HTTP状态与耗时、sessionId/requestId/runId/revision、实际回答/证据/事件、Console、结论、缺陷和复测。令牌及模型Key不进记录或截图。任何“通过”必须有对应实际证据及人工核对。
- 43项均检查，不因平台能力缺失删项。当前没有的目录、审批、账本入口或统计，以具体接口/源码核对证据报告能力缺口；只有页面拒绝或提示并不等于平台目标实现。
- 真实模型不保证按要求生成错误工具参数、环或特定路由。每次记录实际调用，未触发的分支保持未验证；人工提示不是注入已发生，NO_DATA不是工具故障，供应商错误不是本地网关错误。
- 日期按执行当天的服务端语义计算，保留原话并记录实际解析日期；不复用旧2026-10-31为“明天”。停止、重启、只读异常和测试偏好仅作用于可核实的本地演示实例与本次验收数据。

### 公共操作步骤

**P1 新指令与旧结果隔离。** 每个动作使用独立活动任务。提交复合旅行问题并确认GET为RUNNING，记录runId、revision、deadline、modelCalls。用MESSAGE补充座席并另起一条MESSAGE修改日期，用SWITCH切到杭州到成都，用CANCEL停止；省略action时也必须按MESSAGE排队。先读取最新revision，每个动作生成稳定instructionId，重放时保持expectedRevision及原请求内容不变。核对202或200、版本和目标任务；同号异参应返回409；在RUNNING任务上用新instructionId和旧revision提交MESSAGE或SWITCH应返回409。CANCEL不校验版本：用过期revision或省略expectedRevision停止，都必须进入CANCELLED，已停止任务再次CANCEL幂等返回200。等待原任务迟到结果并查询，检查不覆盖修改后状态。若任务太快结束，记录未命中运行窗口，不能用NEEDS_INPUT代替RUNNING断言。父终态不推断所有已受理子级被取消。

**P2 四层幂等。** 保存页面实际提交的sessionId/requestId/question/history，重放同一请求，核对runId与原任务相同、没有新增任务；修改问题但保留requestId，核对409。对指令同样检验同号同参和同号异参。工具和委派层必须补充实际tool-call编号、operationId或缓存回放证据；当前API无这些字段时仅记录已验证请求层，外部写幂等另按2.12处理。无任务号的连接中断先按原编号恢复，不生成新编号。

**P3 真实进程中断与恢复。** 使用独立本地实验实例、独立PostgreSQL数据库和单独日志，浏览器打开该实例同源的同一套静态页面。启动后核对真实模式、Java17、进程命令与端口，记录活动任务和子任务证据；仅对确认归属的实验Java进程制造中断，重新启动同数据库、同认证、同预算的服务。浏览器重新输入令牌并按原runId恢复；记录旧deadline和累计调用。未观察到活动子级或中断前已经完成时不能声称子级恢复通过。实验结束恢复普通真实模式入口，不改用户原有数据库和未提交源码。

**P4 上下文、记忆与压缩。** 先输入“我从杭州去上海，明天出发，二等座”，补充天气、车次、行程偏好并逐轮记录；追问“那后天呢”“改成南京”“换个问题，查杭州到成都的火车票”。通过多轮合法输入积累长历史，每条不超过2000 UTF-16单元，避免发送无意义重复来消耗额度。只有出现实际压缩事件后，再核对早期条件；无压缩则记录未触发，不把超长输入被前端拒绝当压缩成功。召回在独立实验实例显式开启context-recall-enabled后检查实际工具调用；完成后恢复默认开关。

**P5 限流、并发和预算。** 普通入口保持默认预算和串行人工操作，收到429遵守Retry-After，不自动扩大并发重试。需要触发上限时，在独立实例记录实际配置，分别收紧timeout、max-model-calls或max-steps，每轮只改变一个条件；使用真实工具任务观察终态。并发实验逐步增加不同会话，记录负载而不宣称生产QPS。根调用数不能替代步数、token或子级费用；缺少可核对数据的指标保留未验证。不得放宽预算掩盖失败。

**P6 真实故障与重试。** 先区分本地页面请求错误、模型供应商错误、工具错误、无数据。真实服务断连可核对页面恢复；独立实例配置不可连接的模型地址可观察真实连接失败，但不把它说成供应商500或429。供应商限流/配额/5xx和演示工具异常仅在实际出现或有真实可控下游时验收；不创建mock响应、不代理改写真实返回、不编造故障事件。需要下游执行次数或重试间隔而当前无观测时，记录具体阻塞。

**P7 权限与租户。** 独立实例通过环境配置至少四种测试身份：完整权限用户A、仅天气用户B、同租户其他用户C、其他租户用户D；令牌值仅环境和浏览器内存，页面只记别名。AccessPolicy禁止同一tenant/user同时配置不同权限令牌，因此B是不同用户，不能用它证明A撤权。A撤权分支单独重启实验实例，保持A的tenant/user不变、更新唯一有效权限映射；再以A新凭据查询此前任务及历史。测试无令牌401、其他身份任务404、同身份缺证据权限403、无写权限偏好PUT/DELETE403，逐个实际核对，不强行期望工具隐藏返回HTTP403。

**P8 显式偏好生命周期。** 使用专用验收身份，先GET /memories记录基线和版本；通过结构化表单PUT preferredDepartureCity=杭州、preferredSeat=二等座、replyLanguage=中文，设置未来有效期，expectedVersion取实际值。新会话核对偏好，再用旧版本PUT或DELETE验证409；到有效期后重新读取，检查不再装配；当前版本DELETE后确认204和后续查询不包含该值。另发一条“以后回复用中文”的普通对话，核对模型调用 remember_preference 后写入 replyLanguage，来源为 conversation-agent:<runId>；再让工具引用不在用户当前消息中的文字，核对不写入。只清理本次创建的数据，版本不一致先重新读取，不覆盖用户并发更改。当前支持三个键，第一页固定20条通常没有nextCursor；未产生下一页时不能标真实分页已验，非法游标400单独记录。

**P9 循环与计划。** 精确重复、调用图、语义相似和邮箱往返分别建独立任务，先记录实际开关。精确重复只统计非豁免工具同参调用，默认第4次提醒、第5次终止；若缓存回放，核对实际事件，不以五次用户提交替代一次运行内五次tool call。A→B→A或自环必须有真实协作边证据才可判；send_message不启动新回合，不能把往返文字当成调用图。语义检测和规划器默认关闭，独立实例分别显式开启后观察，保留默认关闭对照；语义默认前两次提醒、第三次NEEDS_INPUT，计数依实际工具轨迹。plan_agents仅保存计划，不自动执行；没有实际调用、计数或计划信息的分支均保留未触发或观测阻塞。
