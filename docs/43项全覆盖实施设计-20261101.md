# 43 项全覆盖实施设计（2026-11-01）

## 1. 背景与目标

`Supervisor-v1.2-真实页面验收报告` 的结论是：43 项中通过 1 项、部分验证 29 项、失败 4 项、阻塞 9 项。失败与阻塞不是“页面写得不够多”，而是四类能力缺口：

1. **证据不可见**：计划、父子关系、工具调用配对、委派回执、逐 Agent 用量、压缩与召回记录都存在 `supervisor_tasks.payload` 或检查点里，HTTP 只返回 `RunRes`。
2. **分支不可控**：压缩、召回、循环检测、未知工具、同城规则、故障注入依赖模型自然行为，默认预算和 live 模型下无法稳定复现。
3. **平台能力缺失**：提示词治理、Agent 版本与目录、注册表签名与审计、指标告警、审批、外部写入账本、成本对照没有本地实现。
4. **四项真实缺陷**：压缩丢失关键条件（A4/2.9）、事实校验误判否定句（2.8）、计划工具契约与提示词冲突（2.5）。

本设计的目标不是改报告结论，而是让 43 项各自具备：

- 真实可触发的代码路径；
- 页面可读取的证据；
- 明确的操作入口与触发方式；
- 在默认预算 `60s / 16 次模型调用 / 64 步` 下可重复的验收记录。

## 2. 验收口径与证据规则

用户已确认以下口径，本设计全部遵守：

| 项目 | 规则 |
|---|---|
| 页面证据 | 真实页面逐项通过；源码存在、HTTP 200、旧单测、mock 不能代替页面证据 |
| 治理能力 | 注册表、版本、审批、指标、目录、提示词治理使用本地真实实现，不接外部系统 |
| 外部副作用 | 新增本地真实下游（独立进程、真实落盘、幂等、UNKNOWN 账本、可控故障） |
| 模型分支 | 模型不自然产生目标分支时，允许受控系统提示强制触发，记录必须标注 `triggerMode=CONTROLLED` |
| 供应商错误 | 工具侧用本地真实下游覆盖；模型供应商侧 429/5xx 用测试替身覆盖，报告标注“测试覆盖、非页面证据” |
| 预算 | 默认预算不放宽；复杂任务失败保留真实失败 |
| 受控触发 | 只能强制“运行条件”，不能伪造事件、证据或结果 |

证据记录统一包含：请求字段（去认证）、HTTP 状态与耗时、`sessionId/requestId/runId/revision`、回答、证据、事件、`RunDetail`、关键检查点、构建版本与时间。

## 4. P0：运行证据读模型

### 4.1 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/supervisor/runs/{runId}/detail` | 本计划指定入口；返回 `RunDetailRes` |
| GET | `/api/supervisor/runs/detail/{runId}` | `docs/技术方案.md` 第 11 章的通用详情命名；与本入口同一处理器，作为兼容别名 |
| GET | `/api/supervisor/config` | 脱敏配置证据；不含令牌、密钥、提示词全文 |

两个详情路径都只使用 `@PathVariable`，不引入查询参数；鉴权仍由 `SupervisorRequestFilter` 完成。详情读取先复用 `TaskStoreService.view()` 的归属与证据权限检查，再组装证据，因此不会绕过现有 403/404 语义。

### 4.2 `RunDetailRes` 字段与来源

| 字段 | 来源 | 说明 |
|---|---|---|
| `runId/requestId/sessionId/state/revision/generation/consumedRevision/modelCalls/maxModelCalls/deadline/replacedBy` | `TaskDO` | 运行基础字段 |
| `parentRunId/rootRunId/agentPath/agentRole/accepted` | `TaskDO` | 父子与角色 |
| `agentVersion` | 目录表未落地前固定为 `unregistered` | P3 接入 `agentId@version` 后替换，不伪造版本号 |
| `result` | `TaskDO.result` 或 `progress` 检查点 | 与 `RunRes` 相同的 `ResultDTO` |
| `events` | `TaskDO.events` | 最多 200 条，保持现有截断规则 |
| `plan` | 检查点 `plan:v1:current` | 计划任务、依赖、批次、并行度、token 与延迟估算 |
| `children` | `TaskRepository.all()` 中同 `rootRunId` 且 `agentPath` 以当前路径为前缀的任务 | 含状态、代际、调用数、截止时间、答案与权限 |
| `toolCalls` | 检查点 `loop:v3.3` 的消息内容块 | 按 `callId` 配对 `tool_use` 与 `tool_result`；返回参数指纹、结果摘要、结果字节数、起止时间 |
| `delegations` | `TaskDO.collaborationReceipts` | 键为 `agentTurnId:operationId`；返回操作号、指纹、子运行号、子状态、所需权限 |
| `usage` | 各任务 `loop:v3.3` 中助手消息的 `usage` | 按 `runId/agentPath` 聚合 input/output/cached/total tokens；不估算费用 |
| `spans` | 消息时间戳与 `usage.time` | 模型 span 与工具 span，父 span 为运行；时间格式为 `yyyy-MM-dd HH:mm:ss.SSS` |
| `compactions` | `loop:v3.3` 的 `compactionGeneration/compactionSummary` 与相关事件 | 返回代数、摘要字节数、摘要截断文本、相关事件 |
| `recalls` | 检查点 `context-recall:v1:<n>` | 只返回代数与原始记录字符数、是否存在；不返回原文 |
| `permissions` | 身份、`AgentLifecycle.requiredPermissions`、结果证据工具 | 允许工具、必需工具、被过滤工具、证据复核结果 |
| `promptVersions` | `support/PromptCatalog` | 角色 → promptId/version/hash；P3 迁移到注册表 |
| `checkpoints` | `TaskDO.checkpoints` 白名单 | 排除 `loop:v3.3`、`context-recall:v1:*`、`agent:inherited-history`；单值截断 500 字符 |
| `approvals` | 审批表（P3） | P0 返回空列表，字段契约先固定 |
| `sideEffects` | 副作用账本（P3） | P0 返回空列表，字段契约先固定 |

### 4.3 证据派生规则

1. **工具配对**：遍历快照消息，`tool_use` 建条目，`tool_result` 按 `id` 标记完成；无结果的条目状态为 `PENDING`。参数只返回 SHA-256 指纹，不返回完整参数。
2. **span**：模型 span 的开始时间取助手消息时间戳，时长取 `usage.time` 秒；工具 span 起点取 `tool_use` 时间戳，终点取对应 `tool_result` 时间戳。时间无法解析时返回 `null`，不编造。
3. **用量**：只累计供应商返回的 `ChatUsage`；缺失时为 0，并在 `usage.source` 标注 `provider` 或 `missing`。
4. **压缩**：只返回摘要，不返回被替换的完整对话；摘要截断 2000 字符。
5. **召回**：只返回代数与字符数；原文必须通过 `recall_context` 工具按权限读取。
6. **权限**：`filteredTools = required - allowed`；当前 `view()` 已在权限不足时返回 403，因此详情不会把受限证据暴露给无权限身份。
7. **检查点**：只返回白名单键；`loop:v3.3` 与召回原文永不进入详情。
8. **脱敏**：详情与配置不返回 `Authorization`、令牌、模型密钥、下游密钥、完整提示词。

### 4.4 配置证据 `GET /config`

返回 `ConfigRes`：

- `mode`、`timeoutSeconds`、`maxModelCalls`、`maxOutputTokens`、`maxSteps`；
- `maxConcurrentRequests`、`maxConcurrentPerUser`、`tasksPerUserMinute`、`modelCallsPerMinute`、`modelTokensPerMinute`、`maxStoredTasks`；
- 保留期：`taskRetentionSeconds`、`conversationRetentionSeconds`、`preferenceRetentionSeconds`；
- 策略开关：业务规则、事实校验、语义校验、纠错、多 Agent 模式、planner、主题分段、摘要忠实度、召回、执行限额、循环检测；
- 认证身份：`tenantId/userId/permissions` 列表，**不返回令牌**；
- 数据库类型固定 `h2`，不返回连接串中的账号密码。

## 5. P1：四项失败修复

### 5.1 2.8 事实校验否定句误判

**现状**：`AnswerFactChecker` 扫描回答中所有“数字+单位”与日期，只要证据中没有就加入 `unsupported`；`不会改成 99℃` 因此误判。

**改动**：

1. 增加 claim 抽取：按句切分，标记 `ASSERTION / NEGATION / QUOTATION / HYPOTHETICAL / REQUEST`。
2. 否定、引用用户要求、假设、明确拒绝改值的句子不进入校验；真正的断言仍校验。
3. 冲突证据仍由现有 `EvidenceRenderer` 与 `FACT_CONFLICT` 路径处理，不新增状态码。
4. 测试覆盖：拒绝改值、引用用户要求、假设、真冲突四类。

### 5.2 A4 / 2.9 压缩条件保留

**现状**：`SummaryFaithfulness` 只发告警；`ContextCompactor.replacement()` 在预算不足时静默丢弃早期条件。

**改动**：

1. `ContextCompactor.replacement()` 在摘要前增加“关键条件块”，抽取城市、日期、席别、金额、时长、温度等。
2. 摘要策略增加 `RETRY_ON_MISSING`、`KEEP_CONDITION_VERBATIM`、`FAIL_FAST`：
   - `RETRY_ON_MISSING`：缺失条件追加到摘要提示并重试一次；
   - `KEEP_CONDITION_VERBATIM`：关键条件块原文保留；
   - `FAIL_FAST`：无法保留时发出 `CONTEXT_UNCONFIRMED` 事件，不伪造历史。
3. `ContextRecall` 读取时写入真实回读事件：代数、偏移、回读字节数、来源片段与权限重查结果。
4. 计划检查点 `plan:v1:current` 作为必须保留项。
5. 回归：3 次压缩后仍能回答早期城市、日期、席别。

### 5.3 2.5 计划契约

**现状**：工具描述写“只规划，不派发”，系统提示写“保存计划”，模型据此声称“不落盘”。

**改动**：

1. 描述统一为：“校验计划并写入任务检查点；返回计划与批次，不创建、不派发子 Agent。”
2. 系统提示统一使用“写入计划”。
3. 计划通过 `RunDetailRes.plan` 可查；压缩时保留计划检查点。
4. 增加 ENFORCE 模式样本，计划事件与执行事件分离可见。

## 6. P2：证据暴露与分支触发

按计划逐项实施，全部复用 P0 读模型：

| 能力 | 新表/入口 | 关键证据 |
|---|---|---|
| 子运行、委派、工具配对 | `supervisor_agent_runs`、`supervisor_delegations`、`supervisor_tool_calls` | RUNNING 子快照、`(parent_run_id, tool_call_id)` 唯一键、恢复后配对 |
| 任务书 | `RunDetailRes.children[].taskBrief` | 目标、范围、约束、已核实事实、输出格式、预算、期限、裁剪字节 |
| 故障与重试 | 本地下游故障档位 | `timeout/500/429+Retry-After/reset/lose-response`；成功证据保留 |
| 预算与延迟 | `supervisor_usage` 或检查点聚合 | 逐 Agent token、配额、返还、202 到首事件到完成 |
| 权限与身份 | 权限矩阵 | 目录/执行/证据三层，跨身份 404，撤权 403 |
| 路由、追踪、评测、循环 | `supervisor_spans`、评测集 | 候选与过滤理由、父子 span、20+ 样本准确率、受控触发标注 |

## 7. P3：平台治理能力

严格按照 `docs/技术方案.md` 第 3–11 章既有表与 API 设计实施，不另起方案。关键点：

1. 提示词：`supervisor_prompts`、`supervisor_prompt_versions`；任务创建固定版本，详情返回实际版本与 hash。
2. Agent 版本与目录：`supervisor_agents`、`supervisor_agent_versions`、rollout；任务固定 `agentId@version`，支持灰度与回滚。
3. 注册表安全：manifest HMAC-SHA256 签名，密钥来自 `SUPERVISOR_REGISTRY_SECRET`；启动验签、变更审计、能力白名单、出口 allowlist。
4. 指标告警：从 spans/usage/tasks 聚合，`GET /metrics`、`GET /alerts`；页面只展示真实采集值。
5. 动态目录：20+ manifest，统计候选数、过滤前后数量、Schema 字节、注入预算占比与超预算事件。
6. 审批与外部写入：本地真实下游独立进程，`POST /orders`、`GET /orders/{operationId}`；`book_ticket` 未批准返回 `PENDING_APPROVAL`；账本返回 RUNNING/SUCCESS/FAILED/UNKNOWN。
7. 成本对照：同一目标分别跑单 Agent 与多 Agent，逐 Agent token/费用/耗时。

## 8. P4：安全与记忆合规

1. 内容块信任级别：`SYSTEM/USER/TOOL/RETRIEVAL/CHILD`；工具、子消息、检索内容按数据处理。
2. 记忆候选：`PENDING/APPROVED/REJECTED`，聊天不自动写长期；本地向量索引明确标注本地实现。
3. 删除级联与墓碑、保留期、数据分级、偏好版本/来源/有效期。
4. 数据驻留与导出只做本地可核对字段，不宣称未实现的合规认证。

## 10. 回滚方式

1. 新增接口均为追加，回滚只需移除路由与前端入口，不影响既有 `RunRes`。
2. 新表全部独立，不修改 `supervisor_tasks.payload` 必填字段；回滚时保留表与数据，不删除审计记录。
3. `TaskDO` 新增字段可空，旧任务反序列化后按默认值处理。
4. 实验开关关闭即回到 P0 前行为；P1 修复由测试与开关共同保护，关闭后仍保留原校验路径。

## 12. 风险与边界

1. **P3/P4 是平台建设**：表、服务、页面都需要真实实现，不能只加占位接口。
2. **模型非确定性**：A2/2.13/2.15/2.17 需要受控提示与多次真实样本，不能伪造事件。
3. **供应商侧错误**：只能用测试替身覆盖并标注，可能无法成为页面通过证据。
4. **单实例 H2**：租约、多实例、跨副本删除只能做本地真实演示，不宣称生产级。
5. **文档漂移**：`技术方案.md` 状态表落后于代码，实施时以当前代码与验收报告为准并同步修正。
