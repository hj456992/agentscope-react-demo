# 七项缺口实施设计（2026-10-29）

## 一、范围与目标

依据 `docs/项目问题及解法.md` 第三节，本轮补齐七项能力：

| 编号 | 能力 | 本轮落点 |
|---|---|---|
| 2.14 | 业务语义校验 | 工具执行前的确定性规则：过去日期、超出未来窗口、同城路线 |
| 2.8 | 在线事实校验 | 确定性数值比对、证据冲突降级、高风险可选的 `AnswerVerifier` |
| 2.13 / 2.15 | 纠错次数上限、运行期工具快照、工具不存在兜底 | 运行检查点计数、禁用工具、强制澄清、终态失败 |
| 2.5 | 多 Agent 量化门槛 | 确定性决策函数、`ADVISORY` / `ENFORCE` 运行期硬上限 |
| 2.11 | 统一失败分类 | 429、配额、供应商错误码、`Retry-After`、统一重试判定 |
| 2.9 | 摘要上下文保真 | 压缩保留当前问题与最近工具配对、token 级忠实度告警 |
| 2.7 | 自动话题切分 | 确定性话题信号，只影响历史装配，不删除会话 |

目标：不新增对外 HTTP 错误码、不新增 `Status` 枚举值、不新建数据库表；每项能力可独立配置、独立测试、独立回退。

## 三、跨项设计

### 3.1 策略注入

`Supervisor` 有四参数构造器，测试和入口直接构造点多，不新增第五个参数。新增公开 `SupervisorPolicy` record，通过 `RunControl.policy()` 传入：

- `SupervisorPolicy.defaults()`：七项新能力关闭，多 Agent 为 `OFF`，失败分类开启但行为与现状等价。
- `SupervisorPolicy.standard()`：安全阈值开启，供 Spring 配置使用。
- `RunControl.local(limits)` 保持原行为；新增 `RunControl.local(limits, policy)`。
- `LocalAgentControl.Tree` 保存策略，子节点共享同一份。
- `TaskService.PersistentControl.policy()` 返回任务服务注入的策略。
- `ConversationService` 只接收 `SupervisorPolicy.TopicPolicy`，避免把无关策略带入会话装配。

`SupervisorPolicySettings` 使用前缀 `supervisor.policy`，与现有 `SupervisorSettings` 分开，避免破坏既有四参数测试构造。

### 3.2 默认值与启用节奏

- 阶段 B：类默认关闭；`application.yml` 也保持关闭；新增测试显式传入开启策略。
- 阶段 C：全量测试通过后，`application.yml` 切换为安全开启值，再跑全量并记录。
- 任何一项出现不可接受回归，保留关闭并在实施记录中写明原因。

### 3.3 错误与状态边界

不新增对外 HTTP 错误码，不修改 `SupervisorErrorHandler`，不新增 `Status`。

以下错误码只进入工具结果、`EvidenceDTO.data`、事件或检查点：

`BUSINESS_RULE_VIOLATION`、`TOOL_NOT_FOUND`、`TOOL_DISABLED`、`CORRECTION_EXHAUSTED`、`FACT_CONFLICT`、`FACT_UNSUPPORTED`、`MULTI_AGENT_LIMIT`、`SUMMARY_FIDELITY_MISSING`。

纠错耗尽在 `Supervisor.run` 内转成 `ResultDTO`（`FAILED` 或 `NEEDS_INPUT`），不冒泡为 HTTP 错误。

## 四、分项设计

### 4.1 2.11 统一失败分类

新增 `FailureClass` 与 `FailureClassifier`：

- `RATE_LIMITED`：HTTP 429 且不是配额错误，可重试，优先使用 `Retry-After`。
- `QUOTA_EXHAUSTED`：429 + `insufficient_quota` / `quota_exceeded` / `billing_hard_limit_reached`，不重试。
- `RETRYABLE` / `TIMEOUT`：408、500、502、503、504、连接失败、超时。
- `AUTH`：401 / 403；`INPUT_INVALID`：400 / 422；`NOT_FOUND`：404。
- `CANCELLED`、`BUDGET`、`CONTEXT_LIMIT`：运行控制异常，不重试。
- `UNKNOWN`：其余。

`ToolExecutor.retryable`、`retryDelay` 保留签名，内部委托分类器；`ToolExecutor.attempt` 和 `RunContext.budgeted` 的尝试上限读取 `FailurePolicy`，默认仍为 3 次尝试、最多 2 次重试。`ModelHttpTransport` 用分类器替换 429 特判，保留 `Retry-After` 秒数与 RFC1123 解析。

### 4.2 2.9 压缩保真

重写 `ContextCompactor.replacement`，保持现有 `[保留的用户消息…, 当前问题, 摘要]` 顺序：

1. 识别最后一条真实用户问题，排除摘要、上下文提示、Agent 消息、继承历史标记和工具结果。
2. 当前问题优先保留全文：只按最小摘要预留计算预算；只有问题本身超过窗口时才按 code point 二分截断并标记 `retainedSourcesIncomplete`，截断到 0 仍放不下则抛 `ContextLimit`。
3. 再从新到旧保留真实用户条件；每一步都按**完整摘要**预留空间，放不下就停止，不为旧条件牺牲摘要。
4. 保留最近一组完整工具调用/结果；同样按完整摘要预留，放不下就放弃这一轮配对。工具结果可以截断文本，但不能拆散配对。
5. 摘要最后放；完整摘要放不下时才按 code point 二分截断并标记 `summaryTruncated`。当前问题不会被摘要挤掉，摘要也优先于可重新获取的旧条件和工具结果。
6. 替换成功且 `after < before` 才安装新历史；任何异常都不修改原历史。

> 2026-10-29 回归修正：最初实现给摘要固定预留 1024 字节，离线行程场景中第二次压缩时该预留占满剩余窗口，当前问题被截成 `{"date":"202`，模型因此重复派发子任务并耗尽预算。最终实现改为“当前问题用最小预留、其余保留项用完整摘要预留”，既保住当前问题全文，也保住摘要中的工具状态。

新增 `SummaryFaithfulness`：从压缩前真实用户消息提取日期、城市/路线、座席、金额、分钟、天数等 token，返回保留率、缺失 token、压缩率和是否通过。替换成功写“摘要忠实度”；低于阈值且开关开启时写告警；不改任务状态。

### 4.3 2.14 业务语义校验

新增 `BusinessRuleViolation` 与 `BusinessRules`，只覆盖：

- `DATE_IN_PAST`：日期早于 `context.today`。
- `DATE_TOO_FAR`：日期超过 `today + businessMaxFutureDays`。
- `SAME_CITY`：`query_trains` 的出发地与目的地相同。

`TravelTools.execute` 在权限检查、日期格式检查之后、调用数据源之前校验；违规不执行数据源，返回 `Status.INVALID_INPUT` 证据，`data` 追加 `errorCode=BUSINESS_RULE_VIOLATION`、`ruleId`、`field`、`suggestion`。`matches` 收窄为非空判断，同城只由 `BusinessRules` 判定，避免被通用参数错误吞掉。

### 4.4 2.13 / 2.15 纠错上限与工具快照

新增 `CorrectionType`、`CorrectionDecision`、`CorrectionTracker`：

- 计数键：`correction:v1:<type>:<tool>`、`correction:v1:streak:<tool>`、`correction:v1:total`、`correction:v1:disabled`。
- 计数写入 `RunControl.checkpoint`，重启后恢复。
- 默认阈值：连续 schema 错误 2 次禁用工具；工具不存在 2 次强制澄清、第 3 次失败；业务违规 2 次；总纠错 6 次。

`Supervisor.run` 构建一次完整工具表并固定工具名快照；`registry` 只返回快照内且未禁用的工具。`invoke` 先检查禁用，再处理工具不存在、schema 错误和业务违规。所有工具/协作层的 `onErrorResume` 必须重新抛出 `CorrectionExhausted`，不能吞成普通 `FAILED` 证据。

### 4.5 2.8 事实校验与冲突降级

抽取 `EvidenceRenderer`，`AnswerVerifier` 委托它。新增 `AnswerFactChecker`：

- 从答案提取“数字 + 单位”（℃、元、分钟、张）与显式日期。
- 与成功证据逐项比对：匹配、冲突、无证据支持。
- 同工具同条件出现不同结果时判定 `FACT_CONFLICT`。

`RunContext.evidenceKey` 保留条件字段并追加完整数据指纹；相同条件相同结果仍去重，不同结果保留为冲突证据。收到同条件成功结果时移除旧的 `NO_DATA` / `INVALID_INPUT`。

`Supervisor.finish` 默认执行确定性校验：冲突时用证据渲染替代答案并降级 `PARTIAL`；高风险工具的无证据数值保留原答案并追加提示，降级 `PARTIAL`；只有显式开启语义校验、属于高风险且无冲突时才调用 `AnswerVerifier`。校验器异常只写事件。

### 4.6 2.5 多 Agent 量化门槛

新增 `RoutingInput`、`RoutingDecision`、`MultiAgentGate`，拒绝原因包括：

`TASK_COUPLED`、`PARALLELISM_TOO_LOW`、`AGENT_LIMIT_EXCEEDED`、`DEPTH_LIMIT_EXCEEDED`、`COST_EXCEEDS_BENEFIT`、`LATENCY_GAIN_TOO_LOW`，通过为 `BENEFIT_POSITIVE`。

`MultiAgentPolicy.Mode`：

- `OFF`：不改变现有 spawn 行为。
- `ADVISORY`：只写决策事件。
- `ENFORCE`：执行深度和活动子会话数硬上限，超限返回 `MULTI_AGENT_LIMIT` 工具错误，不创建子会话。

本轮不新增在线规划器；决策函数用于路由评测和 v4.0 阶段 A，文档明确标注。

### 4.7 2.7 自动话题切分

新增 `service/TopicSegmenter`：

- 显式切换词：`换个问题`、`另外问`、`新问题`、`重新开始`、`不聊这个`、`说点别的`。
- 意图变化：天气 / 车票 / 行程 / 未知；当前问题带承接词时不切。
- 话题键由意图、规范化实体和首个问题摘要生成，稳定可复现。

`ConversationService.enrichWithPermissions` 只对服务端历史分段；切换时旧话题只保留一条问题摘要，当前话题仍按“最近 6 轮原文 + 更早问题摘要”装配；`requiredPermissions` 只取当前话题可见轮次；不删除会话行，不改表结构。

## 六、风险与取舍

| 风险 | 缓解 |
|---|---|
| 压缩重写影响面最大 | 先写不变量测试；失败保留原历史；保持消息顺序 |
| 证据键追加指纹改变冲突/去重数量 | 相同条件相同结果仍去重；新增冲突测试；回归 `SupervisorFailureTest`、`SupervisorHttpTest` |
| 策略默认开启改变既有答案或状态 | 类默认关闭，应用配置阶段 C 再开启，每项独立开关 |
| 构造器参数漏改 | 全量编译、Spring 上下文测试、`TestServices` 统一装配 |
| 纠错阈值改变旧测试预期 | 默认关闭；现有 `BUDGET_EXHAUSTED` 用例保持 |
| 话题切分误判 | 确定性规则、严格阈值、默认关闭；只影响历史装配 |

已定取舍：

- 策略走 `RunControl`，不改 `Supervisor` 四参数构造器。
- 不新增对外 HTTP 码、`Status` 值、数据库表字段。
- 2.14 是演示级规则；2026-11-01 已改为配置声明（`supervisor.policy.business-rules`），但没有按工具版本远程下发、租户规则集和写操作 dry-run/审批，这些平台能力留到 v4.0 阶段 A，标注“尚未核实对应实现”。
- 2.9 只做确定性 token 级忠实度评测，不做 NLI/语义模型校验。
- 2.5 做量化决策函数与运行期硬上限，不做在线自动规划器。
- 2.7 使用确定性话题信号，不做向量/模型话题识别，不自动删除旧会话。
- `AnswerVerifier` 保留为高风险可选校验器，语义校验默认关闭。

## 九、2026-11-01 补充设计：循环检测、步数上限、声明式规则与压缩原文召回

用户要求对“部分覆盖和未覆盖”的问题直接实施并跑完测试，不再等待方案审核。本节记录本轮实质设计变更；实现与测试结果回填到 `docs/实施记录.md`。

### 9.1 总步数

- `SupervisorPolicy.ExecutionPolicy(enabled, maxSteps)`，默认关闭；`standard()` 和 `application.yml` 开启，`max-steps=64`。
- `Supervisor.step` 在每个模型回合开始时调用 `RunContext.beginStep`，计数键 `step:v1:<revision>`，同一会话的后续回合不继承上一回合消耗。
- 超过上限抛 `RunControl.BudgetExceeded`，复用 `BUDGET_EXHAUSTED`；不新增 `STEP_LIMIT`、`Status` 或 `SupervisorErrorHandler` 分支。

### 9.2 同工具同参数重复检测

- 新增 `support/ToolCallLoopGuard`，检查点键 `loop:v1:tool-calls`，最多 128 组 `(工具, 规范化参数指纹)`。
- 前 `maxRepeatedToolCalls` 次继续执行；下一次返回 `WARN`，由 `Supervisor.invoke` 转成 `LOOP_DETECTED` 工具错误；再下一次返回 `FAIL`，抛 `CorrectionExhausted(FAILED)`。
- 默认 `max-repeated-tool-calls=3`。协作、询问、召回和计划类工具有意豁免，避免把正常的等待、续问、原文回读和计划校验当成循环。
- 只识别完全相同参数，不识别语义等价参数；计数按任务会话保存。

### 9.3 Agent 调用图回边检测

- 新增 `support/AgentCallGraph`，根任务共享检查点键 `loop:v1:agent-edges`，最多 256 条边。
- `ChildAgentDispatcher` 只在会开启目标新回合的 `spawn_agent`、`followup_task` 前记录 `(caller, callee)`；`send_message` 不进入图。
- 记录前用 DFS 检查 callee 能否到达 caller，自环直接拒绝；成环或超过容量时返回 `cycle=true`，不修改原图，派发器写 `LOOP_DETECTED` 事件并抛工具错误。
- `RunControl.recordAgentEdge` 提供默认空实现，`LocalAgentControl` 与 `TaskService.PersistentControl` 分别落到内存树根和数据库根任务，保持新旧运行控制兼容。

### 9.4 声明式业务规则

- `SupervisorPolicy.BusinessRule(id, tools, type, field, otherField, suggestion)`；类型限定为 `DATE_NOT_BEFORE_TODAY`、`DATE_NOT_AFTER_DAYS`、`FIELD_NOT_EQUAL`。
- `SupervisorPolicySettings` 绑定 `supervisor.policy.business-rules`，按声明顺序构造；未声明或空列表回退内置三条，未知类型、空白标识、缺少比较字段在启动时拒绝。
- `BusinessRules` 按工具过滤、按顺序匹配，命中第一条即返回；仍只输出 `BUSINESS_RULE_VIOLATION` 工具证据，不进入 HTTP 错误码表。

### 9.5 压缩原文召回

- 新增 `ContextRecall`：压缩替换前把原文扁平化写入检查点 `context-recall:v1:<压缩编号>`，最多 120,000 字符；`recall_context` 按压缩编号、`offset`、`limit` 回读，单次最多 8,000 字符。
- `SummaryPolicy` 增加 `recallEnabled`，默认 `false`；原因是工具定义会占用初始工具表预算，默认多 Agent 流程已正好消耗 16 次模型调用，额外压缩调用会让既有 HTTP 用例退化为 `BUDGET_EXHAUSTED`。
- 召回没有独立表、索引 / 向量检索、按记录权限与有效期校验、总召回次数上限；这些仍属平台能力。

### 9.6 测试与边界

- 新增 `LoopDetectionTest`、`StepLimitTest`、`support/AgentCallGraphTest`、`ContextRecallTest`、`BusinessRuleDeclarationTest`。
- 全量测试结果回填 `docs/实施记录.md`；不改变既有 16 项可靠性、权限、记忆和校验能力。
- 未新增对外 HTTP 错误码、`Status` 枚举值或数据库表字段；`SideEffectLedger` 事务例外保持不变。

## 十、2026-11-01 第二批补充设计：语义循环检测与多 Agent 计划器

用户确认继续实施三项：语义环检测、多 Agent 规划器和两者的默认关闭开关。本节记录实质设计变更；两项能力都不新增模型调用，不修改任务状态机和对外错误码。

### 10.1 语义循环检测

- 新增 `support/SemanticLoopGuard`，检查点键 `loop:v1:semantic-goals`。文本先做 NFKC 归一化、转小写、去掉标点和空白，再切成字符双元组，计算 Jaccard 相似度；少于 4 个双元组直接跳过，避免短词误报。
- 工具路径由 `RunContext.checkSemanticToolLoop` 调用，只比较同一工具的规范化参数 JSON，`crossKey=false`；协作路径由 `RunContext.checkSemanticAgentGoal` 调用，跨 callee 比较任务描述，`crossKey=true`。
- 记录写入根任务共享检查点，与 `AgentCallGraph` 一样由父、子会话和重启恢复共用。条目按 `semantic-loop-window` 保留，命中后移到末尾并累计 `warnings`。
- 首次出现写记录并继续；命中且 `warnings <= semantic-loop-max-warnings` 返回 `WARN`，工具路径转 `LOOP_DETECTED` 工具错误，协作路径写事件并抛工具错误；超过提醒次数返回 `ASK`，抛 `CorrectionExhausted(NEEDS_INPUT)`，不直接判失败。
- `LoopPolicy` 增加 `semanticEnabled`、`semanticWindow`、`semanticThreshold`、`semanticMaxWarnings`；`SemanticLoopGuard.record` 校验窗口 1 到 32、阈值 0 到 1、提醒次数大于 0。检查点损坏时抛 `IllegalStateException`，不静默绕过。
- 默认 `semantic-loop-detection-enabled=false`。原因是检测本身不耗模型，但多一个开关意味着默认行为改变；默认关闭也保持与既有 16 次根预算用例一致。

### 10.2 多 Agent 计划器

- 新增 `MultiAgentPlanner`，检查点键 `plan:v1:current`；仅在 `multi-agent-planner-enabled=true` 时由 `Supervisor.allTools` 注册 `plan_agents`。
- 工具入参为 `goal` 和 `tasks`；每个任务包含 `task_name`、`agent_type`、`objective`、`depends_on`。计划器校验任务名 `[a-z0-9_]+` 且不能为 `root`、名称唯一、Agent 类型属于 `weather_agent`、`train_agent`、`itinerary_agent`、目标非空且不超过 2,000 字符、依赖引用存在且不自依赖。
- 用拓扑排序拆 `batches`；还有任务但没有可执行任务时判定 `DEPENDENCY_CYCLE`。按当前身份检查每种 Agent 所需工具权限；检查活动子会话数和深度；`Mode.OFF`、超限或量化门槛不通过时返回 `SINGLE_AGENT` 并附原因。
- token 估算为 `max(256, (goal + objectives 字符数) * 2)`，多 Agent 每个子任务加 64；时延收益为 `max(0, 任务数 - 批次数) * 400ms`；最终复用 `MultiAgentGate.evaluate`，不复制第二套门槛。
- 输出 `decision`、`reason`、`steps`、`batches`、`parallelism`、`estimatedTokens`、`latencySavingMs`、`advice`。计划写入检查点，但**不创建子会话、不自动派发、不调用模型**；模型确认后仍需按批次调用 `spawn_agent`。
- 默认 `multi-agent-planner-enabled=false`、`multi-agent-max-plan-tasks=8`。额外工具定义会占用初始工具表预算，默认关闭避免改变既有 HTTP 与多 Agent 流程。

### 10.3 测试与边界

- 新增 `support/SemanticLoopGuardTest`：相似度、`PROCEED → WARN → ASK`、跨 key 开关、窗口淘汰、短文本、损坏记录。
- 新增 `SemanticLoopTest`：工具参数和协作目标的相似检测、关闭开关不写检查点、模型收到 `LOOP_DETECTED` 后继续、连续相似查询转 `NEEDS_INPUT`。
- 新增 `MultiAgentPlannerTest`：独立任务批次、依赖批次、非法计划、依赖环、子任务上限、无子任务、活动子会话上限、权限拒绝、`plan_agents` 开关。
- 仍未实现：向量或模型语义判断、跨任务树全局调用图、按发送者消息速率配额、模型驱动的在线计划改写、跨任务成本—收益评测集。上述能力标注“尚未核实对应实现”。
- 两项能力均未新增 `Status`、对外 HTTP 错误码或数据库表字段；`SideEffectLedger` 事务例外、声明式事务边界和既有 16 项能力保持不变。
