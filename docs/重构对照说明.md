# Supervisor 重构对照说明

日期：2026-10-28。范围：`src/main/java/dev/garden/demo/supervisor` 全包，以及对应测试、`pom.xml`、接口文档。

本次重构只改变分层、命名、入参来源、事务边界和数据库访问方式；**任务状态机、幂等、预算、重启恢复、副作用账本“先落盘 claim 再调用下游”等行为基线保持不变**。核心 Agent 引擎（`Supervisor`、`RunContext`、`LoopConversation`、`ToolExecutor` 等）仍留在根包，只替换跨层类型引用。

---

## 一、七条要求逐项对照

### 要求 1：controller、service、repo 分别放在独立 package 内

| 改动 | 文件 / 目录 | 说明 |
|---|---|---|
| 新建 controller 包 | `controller/SupervisorController.java`、`controller/SupervisorErrorHandler.java` | 原根包 Controller / ErrorHandler 迁入 |
| 新建 service 包 | `service/TaskService.java`、`service/TaskStoreService.java`、`service/ConversationService.java`、`service/SideEffectLedger.java`、`service/SideEffectReconciler.java`、`service/AccessPolicy.java` | 原根包 service、鉴权与副作用类迁入 |
| 新建 repo 包 | `repo/Database.java`、`repo/JsonCodec.java`、`repo/TaskRepository.java`、`repo/ConversationRepository.java`、`repo/SideEffectRepository.java`、`repo/mapper/*` | 原 `TaskRepository` 拆为三个仓储 + 统一数据库入口 |
| 新建配套包 | `filter/SupervisorRequestFilter.java`、`config/SupervisorConfiguration.java`、`config/SupervisorSettings.java` | 请求前置处理与容器装配独立 |
| POJO 独立 | `pojo/param`、`pojo/req`、`pojo/res`、`pojo/dto`、`pojo/dataobject` | 见要求 2、3 |

验证：`controller/`、`service/`、`repo/` 目录均存在，根包不再有 Controller / Repository / 配置类残留。

### 要求 2：POJO 按接口入参、出参、一般传输对象命名为 xxxReq、xxxRes、xxxDTO

已确认的拆分范围：**跨层边界类型**；算法内部私有 record（`Claim`、`Draft`、`Snapshot`、`CachedChild`、`SavedTurn`、`StoredMemory`、`Key`、`Interruption` 等）保持原样。

| 角色 | 类型 | 位置 |
|---|---|---|
| POST 入参 | `ChatParam`、`InstructionParam` | `pojo/param` |
| 接口入参 | `MemoryReq` | `pojo/req` |
| 接口出参 | `RunRes`、`InstructionRes`、`MemoryRes`、`MemoryPageRes`、`ErrorRes` | `pojo/res` |
| 一般传输对象 | `RequestDTO`、`TurnDTO`、`ResultDTO`、`EvidenceDTO`、`DecisionDTO`、`LimitsDTO`、`IdentityDTO`、`RequestContextDTO`、`DrainResultDTO`、`SideEffectResultDTO`、`SideEffectOutcomeDTO` | `pojo/dto` |
| 领域枚举（跨层） | `Intent`、`Status`、`Action`、`SideEffectStatus`、`SideEffectOutcomeStatus` | `pojo/dto` |

`ChatParam` 提供 `toRequest()` 生成内部 `RequestDTO`；`InstructionParam` 携带 `runId`，因此指令接口不再从 URL 取任务号。

| DO | 对应结构 | 主要字段 |
|---|---|---|
| `TaskDO` | `supervisor_tasks.payload` 的 JSON 聚合 | 任务状态、预算、输入队列、结果、检查点、事件 |
| `TaskRowDO` | `supervisor_tasks` 行 | `runId`、`createdAt`、`payload` |
| `InstructionDO` | `supervisor_instructions` 行 | `runId`、`instructionId`、`fingerprint`、`response` |
| `QuotaWindowDO` | `supervisor_windows` 行 | `windowKey`、`startedAt`、`calls`、`tokens` |
| `SessionDO` | `supervisor_sessions` 行 | `tenantId`、`userId`、`sessionId`、`currentRunId` |
| `ConversationDO` | `supervisor_conversations` 行 | 会话原文、回答、`requiredTools`、创建时间 |
| `MemoryDO` | `supervisor_memories` 行 | 偏好键值、版本、来源、过期、删除标记 |
| `SideEffectDO` | `side_effect_operations` 行 | 操作状态、提交/查询次数、下游响应 |

所有 DO 位于 `pojo/dataobject`，字段使用驼峰命名，由 MyBatis `mapUnderscoreToCamelCase` 映射。

### 要求 4：不使用编程式事务，使用声明式事务

| 改动 | 文件 | 说明 |
|---|---|---|
| 开启声明式事务 | `config/SupervisorConfiguration.java` | `@EnableTransactionManagement(proxyTargetClass = true)`，注册 `DataSourceTransactionManager` |
| 拆分事务服务 | `service/TaskStoreService.java` | 原 `TaskService` 内的所有短事务迁入；公有方法标注 `@Transactional` 或 `@Transactional(readOnly = true)` |
| 会话读写事务 | `service/ConversationService.java` | 类改为非 final，公有方法标注 `@Transactional` |
| 调度与事务解耦 | `service/TaskService.java` | 只保留订阅调度、`owned` 容量和恢复线程，持久化全部委托 `TaskStoreService` |
| 删除编程式事务 | `repo/TaskRepository.java` | 删除 `transaction(Function<Connection,T>)`、`depth`、手动 `commit`/`rollback` |
| 生产代码禁止 `TransactionTemplate` | 全量 grep | 主代码无命中；仅测试夹具 `TestDatabase` 使用 |

事务边界：

| 类 | 方法 | 传播/只读 |
|---|---|---|
| `TaskStoreService` | `create`、`applyInstruction`、`commitResult`、`fail`、`expire`、`cleanup`、`cleanupConversations`、`reserveModel`、`reserveModelStep`、`checkpoint`（写）、`drainInput`、`event` | 默认 REQUIRED |
| `TaskStoreService` | `get`、`all`、`visible`、`view`、`active`、`checkpoint`（读）、`modelCalls` | `readOnly = true` |
| `ConversationService` | `cleanup`、`enrich`、`complete`、`memories`、`put`、`delete` | 默认 REQUIRED |

**有意例外：`SideEffectLedger` 不加 `@Transactional`。** 外部写入必须先以独立语句提交 `RUNNING` claim，再调用下游；如果把 `execute` / `reconcile` 包进一个 Spring 事务，进程崩溃时 claim 会随事务一起回滚，破坏“先落盘再调用”的恢复语义。因此账本在 Hikari autocommit 下逐语句提交，只用私有 `lock` 串行化本地操作。

`TaskStoreService`、`ConversationService` 必须是非 final 公有类，`@Transactional` 方法必须是 public 非 final，CGLIB 代理才能生效；`TaskService` 保持 final，不需要代理。

### 要求 5：鉴权与公共请求头处理放在请求前 filter，不进入接口方法

| 改动 | 文件 | 说明 |
|---|---|---|
| 新增 WebFilter | `filter/SupervisorRequestFilter.java` | 只拦截 `/api/supervisor/**` |
| 统一鉴权 | 同上 | 读取 `Authorization`，调用 `AccessPolicy.authenticate`；失败直接写 401 + `ErrorRes("UNAUTHORIZED", ...)`，不进入 Controller |
| 统一公共头 | 同上 | 读取 `Prefer: respond-async` |
| 上下文传递 | 同上 | 把 `IdentityDTO` 与 `async` 封装为 `RequestContextDTO`，通过 `chain.filter(exchange).contextWrite(...)` 写入 Reactor context |
| 接口取上下文 | `controller/SupervisorController.java` | 私有 `context()` 使用 `Mono.deferContextual` 读取；Controller 不再注入 `AccessPolicy`，不再出现 `@RequestHeader` |
| 顺序 | 同上 | `Ordered.HIGHEST_PRECEDENCE + 10` |

请求链路：

```text
HTTP 请求
  → SupervisorRequestFilter（鉴权、解析 Prefer、写 Reactor context）
  → SupervisorController（context() 取 RequestContextDTO）
  → TaskService / ConversationService（显式接收 IdentityDTO）
```

静态检查：`controller/` 中 `@RequestParam`、`@RequestHeader` 均为零命中。

### 要求 6：POST 只有一个 xxxParam 入参；GET 只有 @PathVariable

| 旧接口 | 新接口 | 入参 |
|---|---|---|
| `POST /api/supervisor/chat` + `@RequestBody Request` | `POST /api/supervisor/chat` | 唯一参数 `@RequestBody ChatParam` |
| `GET /api/supervisor/runs/{runId}` | 不变 | 唯一参数 `@PathVariable runId` |
| `POST /api/supervisor/runs/{runId}/instructions` + body | `POST /api/supervisor/instructions` | 唯一参数 `@RequestBody InstructionParam`（含 `runId`） |
| `GET /api/supervisor/memories?limit=20&cursor=...` | `GET /api/supervisor/memories` | 无参数，固定第一页 20 条 |
| 同上 | `GET /api/supervisor/memories/{cursor}` | 唯一参数 `@PathVariable cursor` |
| `PUT /api/supervisor/memories/{key}` + body | 不变 | `@PathVariable key` + `@RequestBody MemoryReq` |
| `DELETE /api/supervisor/memories/{key}?expectedVersion=1` | `DELETE /api/supervisor/memories/{key}/{expectedVersion}` | 仅路径参数 |

说明：

- 用户已确认 GET/DELETE 一律路径参数，不使用 `@RequestParam`。
- `PUT` 仍按 HTTP 语义使用 `@RequestBody MemoryReq`，与 `@PathVariable key` 并列，不引入查询参数。
- `chat` 的 `Prefer: respond-async` 不再作为方法参数，由 filter 写入上下文。
- 响应码保持不变：异步 202；`FAILED` 502、`TIMEOUT` 504；指令 `CANCEL`/`AUTO` 200，其余 202；删除 204。

## 三、事务与并发边界

| 关注点 | 处理 |
|---|---|
| 事务代理 | `@EnableTransactionManagement(proxyTargetClass = true)`，`DataSourceTransactionManager` |
| 锁顺序 | `TaskService` → `TaskStoreService`；store 不回调 TaskService，避免死锁 |
| 容量检查 | `TaskService` 以 `Runnable` 传入，仅读内存 `owned`，不做 I/O；new/switch 在事务内执行 |
| 会话写入 | `TaskStoreService.create/commitResult` 在事务内调用 `ConversationService.enrich/complete`，经代理加入同一事务 |
| 副作用账本 | 无 Spring 事务；Hikari autocommit 逐条提交；私有 `lock` 串行化 |
| 预算回滚测试 | 仅 `TestDatabase.inTransaction` 使用 `TransactionTemplate`，生产代码不使用 |

## 四、生产类构造器收敛

生产类**只保留一个完整构造器**，依赖全部通过参数传入；不再为单测、权限测试等场景保留构造器重载。测试所需的对象组装统一放在 `src/test` 的辅助类中。

| 类 | 收敛前 | 收敛后 |
|---|---|---|
| `service/TaskService` | 4 个构造器（含单测/权限测试变体） | 1 个：`TaskService(TaskStoreService, SupervisorSettings, BiFunction<...>, AccessPolicy)` |
| `service/ConversationService` | 3 个（含接收 `TaskRepository` 的测试构造） | 1 个：`ConversationService(ConversationRepository, Duration, Duration)` |
| `repo/TaskRepository` | 3 个（含 URL 构造与 `close()`） | 1 个：`TaskRepository(Database, JsonCodec)`；不拥有、不关闭连接池 |
| `service/SideEffectLedger` | 3 个（含 URL 构造与 `close()`） | 1 个：`SideEffectLedger(SideEffectRepository, Clock)`；不拥有连接池 |
| `RunContext` | 2 个（二参构造仅测试使用） | 1 个：`RunContext(RequestDTO, LimitsDTO, RunControl)` |
| `ModelHttpTransport` | 2 个（一个未被任何调用方使用） | 1 个：`ModelHttpTransport()` |

资源所有权随之下移：`Database` bean 由容器通过 `destroyMethod = "close"` 关闭；测试用 `TestRepository`、`TestLedger` 各自持有并关闭打开的 `Database`，生产仓储与账本不再承担关闭职责。
