## 阻塞问题

### P1：行程子任务缓存绕过逐工具权限

位置：`src/main/java/dev/garden/demo/supervisor/ChildAgentDispatcher.java:62-67`，`allowed:102-105`。

`allowed(itinerary_agent)` 接受天气或火车票任一权限；命中 CachedChild 后将全部 evidence 加回上下文并返回原 answer，没有逐条检查当前权限。场景：全权限执行并持久化行程；重启后同一身份只保留天气权限（或撤销 search_knowledge）；恢复同条件行程仍读取火车票/知识数据。原 answer 是所有 facts 的 JSON，因此只过滤 evidence 再原样返回 answer 仍泄漏。ToolExecutor.read 的按单工具鉴权不能覆盖此上层捷径。

修复验收：同一 checkpoint 集合、同一身份降权，缓存中未授权事实不得进入父模型/最终 Result/answer。拒绝缓存或重新运行受权部分均需保持最终状态真实。

### P1：逻辑模型尝试号包含随机消息元数据

位置：`RunContext.java:93`。

`fingerprint(Map.of(model,messages))` 直接序列化 Msg。已读取 AgentScope 2.0.1 sources：`io/agentscope/core/message/Msg.java:710` builder 自动 timestamp，`:736` 自动 UUID；`:267/:312` 对外 getter，JacksonJsonCodec 默认 ObjectMapper 序列化这些字段。同一逻辑模型步骤在重启或重建 Agent 后产生新 hash，从而绕过持久的每步骤三次尝试限制。共享总模型次数仍限制总量，但不是所声明的逻辑步骤恢复限制。

修复验收：两份相同 role/content、不同消息 ID/timestamp/toolCallId 的输入应得到相同逻辑键；内容或模型确实改变则不同。按相同 control 重建 Agent 后，已用尝试次数不能清零。

### P1：用户显式条件仍可被静默忽略

位置：`BusinessConditions.java:14-35`；`SupervisorContracts.Decision`；`AnswerVerifier.java:88-91`。

天数只做上界和原有缺失校验，未对照原文；用户说玩3天而模型 Decision 给1天时可通过。座席等明确限定只留在原始文本，但 Decision/工具不表达也不澄清。已实际执行命令（只运行已有 class，不修改代码）：

`java -cp target/classes:target/agentscope-react-demo.jar dev.garden.demo.supervisor.SupervisorDemo --offline '明天从杭州到上海的火车票，只要一等座'`

返回 SUCCESS；数据源 fixture 及最终渲染为二等座。运行环境未加 `-Dfile.encoding=UTF-8`，终端中文呈问号，但 SUCCESS、TRAIN、query_trains / SUCCESS 可读，Java 路径与代码证明二等座内容。ContextBuilder 保存文本不能等同条件在业务执行中生效。

修复验收：与支持字段对应的明确天数要核验；无法表示但影响结果的显式限定必须澄清，不能以相反条件返回 SUCCESS。此为现有需求正确性问题，不要求扩展新产品能力。

### P2：真实模型 HTTP 429/5xx 不进入新增重试

位置：`RunContext.java:103-104`、`ToolExecutor.java:57-64`。

retryable 仅匹配 TemporaryFailure、ConnectException、SocketTimeoutException、TimeoutException。已读 2.0.1 sources：OpenAIException implements ModelHttpException；429 对应 RateLimitException，5xx 对应 InternalServerException。它们没有必然的 Connect/Timeout cause，因此真实模型 429/503 直接失败，现有 TemporaryFailure 测试只验证自造工具异常。HTTP 401/403/400 应继续不重试，不能笼统接受所有 RuntimeException。

修复验收：使用真实 SDK 异常类分别测试 429、503、401、400；重试次数进入共享预算，未发出任何响应片段才可安全重新采样。服务端 Retry-After 能获得时需遵守，不能从现有工具专用 retryDelay 推断模型已遵守。

### P2：CLI 生成完答案后等待后台调度线程退出

位置：`RunContext.java:22`，`SupervisorDemo.java:28-30`。

静态 newBoundedElastic 三参数重载创建非 daemon 工作线程，CLI 只关闭 HttpTransportFactory。上面的实际 CLI 已打印最终回答及 transport shutdown，exec 仍报告 session 87383 活跃，10秒后继续 poll 仍未退出。随后线程空闲回收，进程自行结束，复查 ps 没有 SupervisorDemo 进程，session 收尾 exit 0。不能把回答已输出等同 CLI 已退出。

修复验收：显式 daemon 或拥有明确容器/CLI 生命周期的 scheduler；一次离线 CLI 输出后应及时 exit。勿停止共享 HTTP 服务里单次请求的全局调度器。
