| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| 1 | 天气成功，车票 Agent 抛错 | 天气仍可返回；车票错误可识别，最终为部分结果 |
| 1 | 第一进程完成天气后被终止，第二进程打开同一数据库 | 有效天气结果不重查；剩余步骤继续；预算与截止时间不重置 |
| 1 | 重启时任务已过期、已取消或已被新版本替换 | 不恢复业务步骤，保留正确终态；未知写入仍由独立核对器查询 |
| 1 | 任务停止后重启，仍有写成功但响应丢失的操作 | 独立扫描查到原结果，不新建写入，不覆盖当前任务 |
| 2 | 旧任务执行中，补充信息或修改日期 | 新版本使用新条件；旧版本迟到结果不能覆盖它 |
| 2 | 先完成天气，再仅修改交通条件 | 有效天气可复用，受影响交通重新查询 |
| 2 | 切换任务或停止，与旧结果提交同时发生 | 只有当前版本可提交当前结果；停止后不启动新步骤 |
| 2 | 同一指令重发；不同内容复用同一编号；过期版本修改 | 分别返回原结果、409、409，无重复修订 |
| 2 | 自动识别有歧义或预算耗尽；容量不足 | 提示明确动作或返回繁忙，原任务不被误取消 |
| 2 | 待补充未过期、已过期，或同会话已开启新任务 | 分别可接续、409、409；等待补充不占执行名额 |
| 3 | 多个子 Agent 并发调用，剩余模型额度只有 1 | 实际最多一个请求成功占用额度，合计不超上限 |
| 3 | 故障重试、回答纠错、摘要和恢复执行 | 每次真实模型调用计数，已发送或发送不确定的额度不返还 |
| 3 | 全局准入拒绝；重启前已经用完局部重试和纠错次数 | 未发送且拒绝的请求不扣任务额度；局部次数恢复后不能清零 |
| 3 | 模型很慢、工具很慢、退避超过剩余时间 | 以适用的最短截止时间结束，任务不无限挂起 |
| 3 | 达到全局调用/Token额度后新请求到达 | 不调用供应商，返回明确限流，重启不刷新窗口额度 |
| 4 | 同一操作相同参数并发提交多次 | 下游写入次数为 1，返回同一业务编号 |
| 4 | 同一操作号携带不同参数 | 冲突，不产生第二次写入 |
| 5 | 单独天气、单独车票、组合规划 | 前两者只进入对应 Agent，规划确实复用两个查询 Agent |
| 5 | 查询 Agent 试图调用其他角色工具 | 无实际执行，不可越过工具边界 |
| 6 | 相同子任务在同一轮被重复提出 | 合并执行或复用成功结果，不产生重复查询 |
| 6 | 日期、来源版本或结果有效期改变 | 不能复用失效结果；不同用户之间不共享私有任务结果 |
| 6 | 子 Agent 自由文本编造价格 | 父任务不能把它当作结构化查询事实 |
| 7 | 多轮省略问题，之后重启服务 | 从同一用户的服务端历史恢复必要条件 |
| 7 | 两用户相同 sessionId；两租户同名用户 | 会话、摘要和偏好均隔离 |
| 7 | 确认偏好、更新、过期、删除 | 下一轮正确生效；删除偏好不从旧摘要复活 |
| 7 | 模型猜测偏好，或临时指定某日行程 | 不自动写成长期偏好 |
| 8 | 检索到正确条款，模型引用不存在编号或改写关键数值 | 错误结论不能直出，触发受限纠错或证据化降级 |
| 8 | 工具价格为 80，模型写为 800；天气只查一天却描述多天 | 事实输出回到真实证据，不能扩大证据适用范围 |
| 8 | 资料过期、版本变化、检索原文含越权指令 | 无效资料不作为依据，文本不能获得工具权限 |
| 9 | 很长历史最早一轮包含预算/日期，近期消息有修正 | 最新明确条件优先，关键约束保留 |
| 9 | 单条工具返回很长，或工具定义已占满窗口 | 保留关键字段/引用；必需内容放不下时明确失败，不截断关键条件 |
| 9 | 整理模型历史 | 工具请求与响应保持配对，完整请求处于配置预算内 |
| 10 | 并行步骤一成功一失败；依赖失败结果的步骤等待 | 成功结果保留，独立工作继续，依赖步骤不带空参数执行 |
| 10 | 第一次尝试失败，后续修正成功 | 最终状态按最终有效结果判断，不被历史失败污染 |
| 11 | 连接短暂失败后恢复、429 带 Retry-After | 有限退避和总预算共同生效，实际尝试次数可核对 |
| 11 | 无权限、未知工具、结构错误、业务拒绝 | 不原样重试；可修正错误有限修正，其他明确结束 |
| 12 | 下游写成功，但响应丢失 | 查询原操作号确认成功，不能创建第二笔效果 |
| 12 | 写入完成、本地成功记录未落库时终止进程 | 重启先查询下游，回填原结果，实际写入次数仍为 1 |
| 12 | 下游无法查询且不支持幂等 | 保持结果待核对，不盲目重放，不伪造失败或成功 |
| 12 | 本地过期清理后重发旧操作号 | 仍能拒绝或核对旧操作，不能因记录清理重复写入 |
| 13 | 选错工具、缺字段、类型错误 | 可识别字段级错误；超过纠错上限后结束 |
| 13 | 一直重复错误工具调用 | 工具选择预算和全局模型预算都能终止循环 |
| 14 | 日期格式合法但与用户要求不同、路线相反 | 业务校验拦截，不只比较格式 |
| 14 | “不是上海，是杭州”等修正或无法确定的指代 | 保留明确修正；无法确定则澄清 |
| 15 | 模型生成未注册工具名 | 实际执行次数为 0，返回 TOOL_NOT_FOUND，不宣称成功 |
| 16 | 未认证、过期令牌、权限不足、伪造用户/租户字段 | 返回适当错误，没有任何实际工具副作用 |
| 16 | 任务号属于别人、缓存结果已存在但权限被撤销 | 不返回他人结果，重放前重新授权 |

## 执行层次与证据

1. 逻辑测试：注入时钟、延迟、失败与受控模型输出，验证边界和竞争。
2. SDK 调用链：保留真实 AgentScope 编排与工具调用，离线模型只替代生成服务。
3. Spring HTTP：六个接口的身份、参数、状态码、幂等重放、取消及容量释放。
4. 进程恢复：两个独立 JVM、同一任务库、独立下游测试库，实际中断并重新启动。
5. 网络请求：真实监听并调用；如果环境仍拒绝绑定，记录原因，不用内存请求冒充网络验收。
6. 模型效果：真实供应商调用与离线脚本分开记录，未调用就明确写未验证。

每条结果记录对应测试名、实际断言和执行报告。说明文档最终引用这些证据，不把本用例清单本身当作测试通过。
