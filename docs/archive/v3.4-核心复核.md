## 取消后的新回合

独立 child followup 通过带来源 mailbox 提供新任务，`agent:turn-start` 只重开回合，不合成一条真实用户消息。取消后的同一 HTTP session 新 chat 则由存储层复制最近取消根的 loop 检查点，并设置 `agent:resume-user-input` 为这次真实输入。

`LoopConversation.java:117-142` 以 turn ID 幂等处理：重置本轮结果状态、正规化旧 pending、添加内部中断告知、按来源接入新输入，然后先保存完整快照再清标记。标记清除前崩溃重放不会重复添加用户文本。`ContextCompactionTest.resumedRootAddsNewRealUserInputAndAbortsOldPendingToolExactlyOnce` 覆盖这条边界；HTTP 存储集成由生命周期回归覆盖，不能用 child 单元测试替代。

## 仍需如实保留的边界

6656 是当前 JSON UTF-8 输入字节限额；它不是 Codex token 窗口，也不是模型供应商实际 token 计数。上游 local 的 20,000 近似 token 用户保留上界还要受当前真实请求剩余空间约束。替换无缩减、摘要单独超限会失败，不能无限重复压缩，也不能承诺原文永久无损。

Java Chat Completions 传输、模型兼容 hash、远端/后台压缩、hook、world-state、Agent 模型覆盖与 residency 等差异继续列在适配边界文档。KnowledgeService 与 AnswerVerifier 作为可复用组件存在，不是当前核心终答必经步骤；Schema/权限检查不能冒充自然语言条件和事实忠实性保证。这些是待对齐事项，不以旅行场景或 Demo 为理由删除要求。
