## 4. 本轮修复与实现要点

1. 上下文输入上限改为配置项 `supervisor.policy.context-input-limit`，默认 8192 字节，不再写死在 `ContextBuilder`。工具 Schema 与系统提示约 6.4KB，原上限只给当前问题不到 200 字节，导致同一会话第二轮换题出现 `CONTEXT_LIMIT`；目录 Schema 注入预算仍为 6656 字节，A1 的 8887/6656 超预算证据不受影响。
2. 429 响应增加 `Retry-After: 1`，并发探针实测响应头为 `1`。
3. P0–P4 新增的运行详情、治理、审批、账本、指标、目录、提示词、记忆和本地下游能力沿用前序实现；本轮补充 A3/2.7、B2、B3、B4、2.11、2.16 的页面证据。

## 5. 已知读模型差异

补充/修改指令被消费后，`GET /runs/{runId}` 与详情中的 `result.originalQuery` 可能显示当前指令文本（例如“补充：只需要杭州天气”），而页面仍保留原问题作为该轮标题。该差异不影响任务终态、指令版本、证据和幂等判断；B5/2.2 的结论依据是 revision、指令重放结果和页面动作反馈。若后续要求 `originalQuery` 永远保持首轮问题，应单独修改读模型并补回归，不在本轮验收中把它伪装成已一致。
